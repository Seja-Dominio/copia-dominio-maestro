# Maestro — matriz inicial de impacto do ledger Dev

Atualizado em 05/10/2026. Este documento registra uma triagem por conteúdo SQL; não autoriza replay, reparo do ledger, DDL hospedado ou deploy. O CXM está fora do goal e aparece apenas para explicitar exclusões e dependências compartilhadas.

## Base factual

- Projeto Dev explicitamente confirmado: `tqmfuskvllpqmvayjuqu`. Produção: `fwpisypiiezjhtqxlmqv`.
- Ledger Dev consultado sem escrita: 88 versões remotas. O checkout de estabilização tem 18 arquivos: 16 correspondem por identidade e conteúdo; `0004` tem conteúdo diferente; `20260917150839_dominus_learning_review_comments` é local-only; 71 IDs remotos não existem no checkout. Existem 72 conteúdos remotos não representados, pois o conteúdo remoto de `0004` também diverge.
- A branch candidata `codex/maestro-db-canonical-candidate` (`100bbbad`) contém 187 migrations, mas não é uma sequência reconciliada para o ledger Dev: a auditoria por fingerprint encontrou 25 pares identidade+conteúdo, 9 identidades com conteúdo diferente, 45 conteúdos idênticos sob outro versionamento e 18 conteúdos remotos sem equivalente no checkout candidato. Não escolher essa sequência apenas pela quantidade de migrations ou aliases.
- A triagem completa por identificadores SQL separou os 72 conteúdos ausentes do checkout ativo em grupos Maestro/Core, Financeiro, Ads Brain, plataforma multi-tenant, mutations compartilhadas e CXM. - Nenhum schema, ledger, cron, dado de negócio, Edge Function ou serviço de Produção foi alterado neste trabalho.
